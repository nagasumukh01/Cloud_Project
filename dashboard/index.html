TrustProof-Cloud System Architecture

Understanding the distinction between Cryptographic Integrity and Computational Correctness.

1. Cryptographic Integrity (What Crypto Solves)

Every inference result is wrapped in an Ed25519-signed envelope binding task_id, worker_id, model_version, input_commitment (BLAKE2b-256), result_hash (SHA-256), and timestamp/nonce for replay protection.

2. Computational Correctness (What Policy Solves)

A worker with a valid private key can sign a wrong answer. Rather than replicating everything, the engine computes risk R in [0, 1] and allocates verification budget dynamically:

R < 0.25 (tau_low) → Accept unverified (cost = 1.0)
R < 0.65 (tau_high) → 1 independent verification (cost = 2.0)
R ≥ 0.65 → N replicas / Quarantine (cost ≥ 3.0)
